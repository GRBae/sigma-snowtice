# 위키 페이지 규칙 (SCHEMA)

위키 md는 **SNOWCHAT Agent A(공지 정보) 전용 지식 파일**이다. 웹은 위키를 쓰지 않고 그래프(DB)를 바로 읽는다.

## 만드는 방법
- 페이지는 `pipeline/render.py`가 그래프에서 템플릿(`templates/*.md.j2`)으로 찍는다. **사람·LLM이 페이지 본문을 직접 고치지 않는다.** 틀린 곳은 추출 JSON이나 그래프 규칙을 고친 뒤 다시 렌더한다.
- LLM이 쓰는 곳은 '한눈에 보기' 요약 2~3줄뿐이다. LLM 설정 전에는 코드 요약을 쓰고 끝에 `(코드 요약)`을 붙인다.

## 파일 단위 (SNOWCHAT 지식 파일 100개 한도)
| 파일 | 내용 |
|---|---|
| `절차_{학기}_졸업_공통.md` | 본부 졸업 절차 |
| `절차_{학기}_졸업_{학과}.md` | 본부 절차 + 학과 단계. 학과 마감이 본부와 다르면 학과 값을 쓰고 본부 기간을 함께 적는다 |
| `절차_{학기}_조기졸업.md` | 조기졸업 |
| `규정_졸업_공통.md` | 학기와 무관한 자격·결과·유의사항. 고정 안내의 '대략적 시기'는 참고로만 적고 날짜는 학기 공지가 우선 |

## 내용 규칙
- 날짜는 그래프 값 그대로, 요일을 붙인다. 상세 공지 전 날짜는 `(예정·변동 가능)`, 검증 실패는 `[확인 필요]`, 날짜 없음은 `일정 미정 [확인 필요]`.
- 섹션 제목마다 `(학기 졸업 · 학과)`를 붙인다. SNOWCHAT이 파일을 조각내 검색해도 어느 절차인지 알 수 있게.
- 대상 표시: `(필수)`, `(해당자)`, `[수료생만]`, `[2001~2019학번만]`.
- 모든 페이지 끝에 근거 공지(제목·게시일·링크)와 문의처를 붙인다. 개인 이메일·이름은 넣지 않는다.

## 운영
- 매일: crawl → verify → build_graph → render → lint. 바뀐 파일만 SNOWCHAT에 다시 올린다 (`log.md`에 기록).
- 유효기간(`유효: ~날짜`)이 지난 학기 파일은 만들지 않고 `index.md`의 '끌 파일'에 올린다 → SNOWCHAT에서 해당 파일을 끈다.
- `lint_report.md`는 팀 내부용이다. 올리지 않는다.
